# agent-kit

Набор общих правил для ИИ-агентов (Claude Code, Codex и других), которые работают в твоих
проектах, и шаблоны, по которым устроен каждый проект. Идея простая: агент каждый раз
приходит без памяти, поэтому всё, что ему нужно знать о проекте, лежит в самом репозитории
в одних и тех же файлах, а правила поведения — в одном месте, а не в каждом чате.

## Что внутри

| Путь | Что это |
|---|---|
| `releases/v1.0/CORE.md` | Ядро: что агент делает сам, а на что спрашивает разрешение; как отличать наблюдение от вывода; Git, секреты, язык. Агент читает его всегда |
| `releases/v1.0/PROJECT.md` | Раскладка проекта: какие файлы бывают (`STATUS`, `DECISIONS`, `LESSONS`, `HISTORY`…) и как в них пишут |
| `releases/v1.0/STATUS.md` | Как писать сводку проекта — пять полей, которые ты читаешь за десять секунд |
| `releases/v1.0/modules/` | Необязательные модули: `clusters` (Slurm, GPU, удалённые машины) и `research-experiments` (планирование и интерпретация экспериментов) |
| `plugin/` | Плагин для Claude Code: при старте сессии проверяет, что копия kit в проекте не испорчена, и даёт навык `/new-project` |
| `CHANGELOG.md` | Выпуски и хеш манифеста каждого |

Выпуск неизменяем: правила меняются новым выпуском (`releases/v1.1/`), а проекты переходят
на него явно. Поэтому агент в проекте всегда знает, по какой версии правил он работает.

## Как устроен проект

```
my-project/
├── AGENTS.md            вход для агента: что это за проект, что читать, ограничения
├── CLAUDE.md            одна строка @AGENTS.md (Claude читает CLAUDE.md, Codex — AGENTS.md)
├── agent-kit/v1.0/      копия выпуска kit (чтобы правила были под рукой на любой машине)
└── docs/
    ├── STATUS.md        ## Project summary — где мы сейчас, что дальше, что нужно от тебя
    ├── DECISIONS.md     твои решения и открытые вопросы к тебе
    ├── LESSONS.md       уроки: что не сработало и какое правило из этого вышло
    └── HISTORY.md       хронология, только дописывается
```

Остальные файлы (`DIRECTION`, `RULES`, `PROVENANCE`, `OPERATIONS`, `NAMES`, отчёты)
появляются, когда в проекте есть то, что в них живёт, — подробно в `PROJECT.md`.

## Начать за десять минут

1. Склонируй этот репозиторий, например в `~/code/agent-kit`.
2. Поставь плагин в Claude Code:
   ```
   /plugin marketplace add ~/code/agent-kit
   /plugin install agent-kit@agent-kit
   ```
3. Новый проект: в Claude Code скажи `/new-project garden-planner планировщик посадок`.
   Агент уточнит название и цель и создаст `~/code/garden-planner` по раскладке, с копией kit
   и первым коммитом. Без Claude то же самое делает скрипт:
   ```sh
   bash plugin/skills/new-project/scripts/new_project.sh garden-planner \
     --title "Garden planner" --purpose "Plans what to plant and when." \
     --objective "планировщик посадок" [--modules clusters] [--github]
   ```
   `--github` сразу публикует проект приватным репозиторием (нужен `gh auth login`).
4. Открой папку проекта в Claude Code или Codex и дай первую задачу. Агент начнёт с
   `AGENTS.md`, а после работы обновит `docs/STATUS.md`.

**Существующий проект.** Скопируй `releases/v1.0/` в `agent-kit/v1.0/` проекта, возьми
`AGENTS.md` и `docs/*` из `plugin/skills/new-project/templates/` (подставь свои значения
вместо `{{…}}`) и попроси агента перенести туда то, что сейчас разбросано по README и чатам.

## Под себя

- Правила написаны от лица «владельца» — это ты. Язык сводок для владельца — русский
  (`CORE.md`, раздел «Язык»); если хочешь другой, поменяй это в своём выпуске.
- Хочешь изменить правило — не правь копию в проекте: сделай `releases/v1.1/` с новым
  `MANIFEST.sha256` (`cd releases/v1.1 && sha256sum $(find . -name '*.md' | sort) > MANIFEST.sha256`),
  запиши хеш в `CHANGELOG.md` и переведи проекты на новый выпуск.
- Проверить копию kit в проекте:
  ```sh
  (cd agent-kit/v1.0 && sha256sum -c MANIFEST.sha256)   # macOS: shasum -a 256 -c
  ```
  а хеш самого `MANIFEST.sha256` сверить со значением в `AGENTS.md`.

## Почему так

- **Память — в репозитории, а не в агенте.** Память конкретного приложения видит только
  оно; файл в Git видят все агенты и ты сам.
- **Разрешение — словами владельца.** Молчание, зелёные тесты и «ты же вчера разрешил» —
  не согласие на публикацию, деплой или новые ресурсы.
- **Одно место для каждого факта.** Статус ссылается на решения и уроки, а не пересказывает
  их: две копии быстро расходятся.
