# agent-kit

Начало твоей агентской среды: общие правила для ИИ-агентов, плагин для Claude Code и
шаблоны, из которых собирается всё остальное — репозиторий памяти, рабочие проекты,
служба на сервере, рутины. Идея одна: агент каждый раз приходит без памяти, поэтому всё,
что ему нужно знать, лежит в git в одних и тех же файлах, а правила поведения — в одном
месте, а не в каждом чате.

**С чего начать: [SETUP.md](SETUP.md)** — по шагам, от пустого места до работающей среды.

## Что внутри

| Путь | Что это |
|---|---|
| `SETUP.md` | Как собрать среду: память, координатор, проекты, сервер, рутины |
| `releases/v1.0/CORE.md` | Ядро правил: что агент делает сам, а на что спрашивает разрешение; как отличать наблюдение от вывода; Git, секреты, язык. Агент читает его всегда |
| `releases/v1.0/PROJECT.md` | Раскладка проекта: какие файлы бывают (`STATUS`, `DECISIONS`, `LESSONS`, `HISTORY`…) и как в них пишут |
| `releases/v1.0/STATUS.md` | Как писать сводку проекта — пять полей, которые ты читаешь за десять секунд |
| `releases/v1.0/modules/` | Необязательные модули: `clusters` (Slurm, GPU, удалённые машины) и `research-experiments` (планирование и интерпретация экспериментов) |
| `plugin/` | Плагин для Claude Code: при старте сессии проверяет копию правил в проекте; навыки `/new-notes`, `/new-project`, `/kit-upgrade` |
| `templates/notes/` | Каркас репозитория памяти: задачи, направления, журнал, память агентов, передача работы, валидатор |
| `templates/` | Инструкции проекта-координатора, служба Remote Control для сервера, пример рутины |
| `scripts/release.sh` | Новый выпуск правил: `new`, `seal`, `check` |
| `AGENTS.md` | Вход для агента, который сопровождает сам kit, и порядок изменения правил |
| `LESSONS.md` | Уроки о поведении агентов, общие для всех проектов, — из них растут следующие выпуски |
| `CHANGELOG.md` | Выпуски и хеш манифеста каждого |

Выпуск неизменяем: правила меняются новым выпуском (`releases/v1.1/`), а проекты переходят
на него явно. Поэтому агент в проекте всегда знает, по какой версии правил он работает.

## Как устроен рабочий проект

```
my-project/
├── AGENTS.md            вход для агента: что это за проект, что читать, ограничения
├── CLAUDE.md            одна строка @AGENTS.md
├── agent-kit/v1.0/      копия выпуска kit (чтобы правила были под рукой на любой машине)
└── docs/
    ├── STATUS.md        ## Project summary — где мы сейчас, что дальше, что нужно от тебя
    ├── DECISIONS.md     твои решения и открытые вопросы к тебе
    ├── LESSONS.md       уроки: что не сработало и какое правило из этого вышло
    └── HISTORY.md       хронология, только дописывается
```

`/new-project` создаёт эти файлы с заголовками; как в них писать — `PROJECT.md` §2, §3 и §8.
Остальные (`DIRECTION`, `RULES`, `PROVENANCE`, `OPERATIONS`, `NAMES`, отчёты) появляются,
когда в проекте есть то, что в них живёт.

## Быстрая проверка без Claude

```sh
bash plugin/skills/new-notes/scripts/new_notes.sh --dir /tmp/try
bash plugin/skills/new-project/scripts/new_project.sh garden-planner --dir /tmp/try \
  --title "Garden planner" --purpose "Plans what to plant and when." --objective "планировщик посадок"
```

## Почему так

- **Память — в репозитории, а не в агенте.** Память конкретного приложения видит только
  оно; файл в Git видят все сессии и ты сам.
- **Разрешение — словами владельца.** Молчание, зелёные тесты и «ты же вчера разрешил» —
  не согласие на публикацию, деплой или новые ресурсы.
- **Одно место для каждого факта.** Статус ссылается на решения и уроки, а не пересказывает
  их: две копии быстро расходятся.
