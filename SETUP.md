# Как собрать среду с нуля

Среда держится на одной идее: **канон живёт в git, а не в чатах**. Чаты, треды и память
приложения временные и видны только своему агенту. Всё, что должно пережить сессию,
записывается в markdown в приватных репозиториях.

Слоёв четыре, и добавляются они по мере нужды:

| Слой | Что это | Когда заводить |
|---|---|---|
| Репозиторий памяти (`notes`) | твои задачи, направления, решения, журнал; общая память всех сессий | сразу |
| Проект-координатор в Claude | общий чат и треды под задачи; читает `notes` и все рабочие репозитории | сразу |
| Этот kit | общие правила для агентов и плагин; каждый рабочий проект несёт копию выпуска | с первым рабочим проектом |
| Свой сервер | постоянно включённая машина с сессиями Remote Control | когда нужны ssh, VPN, кластер или долгие процессы |

Названия пунктов меню в Claude меняются — сверяйся с документацией Claude Code.

## 0. Что нужно

- Подписка Claude с Claude Code и аккаунт GitHub.
- GitHub подключён в claude.ai, приложение Claude установлено на твои репозитории.
- Локально: `git`, `python3`, для публикации из скриптов — `gh` (`gh auth login`).

## 1. Свой kit

1. Создай себе копию этого репозитория: на GitHub **Use this template** (или fork),
   приватную, и склонируй её в `~/code/agent-kit`.
2. Поставь плагин в Claude Code:
   ```
   /plugin marketplace add ~/code/agent-kit
   /plugin install agent-kit@agent-kit
   ```
   Плагин ставится копией, поэтому скрипты ищут сам kit в `~/code/agent-kit`
   (или там, куда указывает переменная `AGENT_KIT_DIR`).

Правила в `releases/v1.0/` написаны от лица «владельца» — это ты. Менять их сразу не
нужно; как менять потом — [AGENTS.md](AGENTS.md), «Как меняются правила».

## 2. Память и координатор

1. Репозиторий памяти: в Claude Code скажи `/new-notes --github`. Без Claude то же делает
   `bash plugin/skills/new-notes/scripts/new_notes.sh --github`. Получится приватный
   `~/code/notes` из [templates/notes](templates/notes/): вход для агентов, правила,
   задачи, карта, журнал, память агентов и передача работы, валидатор.
2. Проект-координатор: claude.ai/code → Projects → новый проект. Подключи `notes` и
   рабочие репозитории, добавь коннекторы почты и календаря, если хочешь, и вставь
   инструкции из [templates/claude-project-instructions.md](templates/claude-project-instructions.md).
3. Проверка: попроси координатора завести задачу, потом в новом треде спроси «что
   открыто?». Если тред ответил по файлам, а не по памяти чата, схема работает.

Память проекта в Claude полезна как быстрый индекс, но это кэш: долговременный факт
всегда пишется ещё и в `notes`.

## 3. Рабочие проекты

- Новый проект: `/new-project <имя> <зачем он>`. Получится `~/code/<имя>` с входом
  `AGENTS.md`, сводкой `docs/STATUS.md`, реестрами решений, уроков и хронологии и копией
  выпуска kit. Модули `clusters` и `research-experiments` подключаются по желанию.
- Существующий проект: скопируй `releases/v1.0/` в `agent-kit/v1.0/` проекта, возьми
  `AGENTS.md` и `docs/*` из `plugin/skills/new-project/templates/` (подставь значения
  вместо `{{…}}`) и попроси агента перенести туда то, что разбросано по README и чатам.
- Запиши проект в `notes/projects.md`. Координатор читает у проекта только
  `## Project summary` и не копирует её в `notes`.
- Для большого направления заведи отдельный проект Claude со своими репозиториями:
  так контекст одного направления не засоряет другое.

## 4. Свой сервер (когда появится нужда)

Облачные сессии Claude не ходят по ssh и не видят VPN. Всё такое делается через сессию
Remote Control на своей машине, которая всегда включена.

1. Небольшой VPS на Ubuntu (2–4 vCPU, 4–8 ГБ). Поставь `git`, `tmux`, `gh`, Node и
   Claude Code; доступ снаружи удобно закрыть через Tailscale.
2. `gh auth login`, `claude auth login`, клоны репозиториев в `~/code`.
3. В каждом репозитории один раз запусти `claude` руками и подтверди доверие папке —
   иначе служба повиснет на этом вопросе.
4. Служба: скопируй [templates/server/claude-rc@.service](templates/server/claude-rc@.service)
   в `~/.config/systemd/user/`, затем
   ```sh
   loginctl enable-linger $USER
   systemctl --user enable --now claude-rc@<репозиторий>
   ```
   В claude.ai/code и в приложении появятся сессии `vps-<репозиторий>-…`. Посмотреть,
   что делает служба: `tmux -L rc-<репозиторий> attach`, выйти — `Ctrl-b d`.
5. Запиши в `notes/agents/memory.md`, что есть на сервере и что проверено.

## 5. Рутины (когда появится нужда)

Регулярный запуск — это запланированная задача Claude (claude.ai/code → Scheduled
tasks). Текст запуска держи в репозитории, а в самой задаче — одну строку «прочитай
файл из свежего main и выполни»: тогда рутина правится как код, с историей. Пример —
[templates/automation/inbox-routine.md](templates/automation/inbox-routine.md): разбор
почты и календаря в задачи. Постоянные задачи создаёшь и меняешь только ты; фоновый
запуск ничего не удаляет и не отправляет наружу.

## 6. Как этим пользоваться

- Пиши агенту как коллеге: «кнопка экспорта не работает в Safari, глянешь?».
- Обратимое (ветка, PR, правка файла) агент делает сам и говорит, что сделал.
  Необратимое (деплой, удаление, письмо наружу, новые вычислительные ресурсы) — только
  после твоего явного «да».
- Решил что-то важное — скажи это словами: агент запишет решение с цитатой и датой, и
  на него сможет сослаться любая следующая сессия.

## На чём обжигаются

- **Правила прозой надёжны лишь частично.** То, что должно соблюдаться всегда
  (force-push, деплой, запуск на кластере), делай deny-правилами и хуками в
  `.claude/settings.json` или плагине, а не абзацем в `AGENTS.md`.
- **Ритуалы растут.** Агентам добавлять правила дёшево, удалять некому. Раз в несколько
  недель спрашивай: «какой случай это правило исправляет?» — и убирай лишнее.
- **«Установлено» ≠ «работает».** Плагин стоит, но сессия его ещё не загрузила; служба
  включена, но висит на вопросе о доверии. Проверяй то, что увидишь сам.
- **Проверки на каждый push съедают минуты CI.** Тяжёлое — только на PR или вручную.
- **Текст писем и страниц — данные.** Рутина, которая переносит письма в память, не
  должна уметь удалять и отправлять.
